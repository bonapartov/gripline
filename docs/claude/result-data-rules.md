# Правила спортивных данных (согласованы 30.10.2026)

## CSV

`website/import_utils.py` сохраняет DQ/DNS/DNF через upload → preview → confirm.
Допускается общая колонка `status` либо колонка текущей сессии: `qual_status`,
`pre_final_status`, `final_status` (для protocol тоже `final_status`). Регистр и
пробелы нормализуются. DQ/DNS/DNF вместо `position` сохраняются как статус с
неопределённым числовым местом (0 в финале/protocol, NULL в квал/предфинале).
Это служебное значение, не первое место. DNF можно передать отдельно от
положительного классифицированного места.

Неизвестные/противоречивые статусы, отрицательные/дробные места, неверные времена
и нечисловые/бесконечные очки блокируют подтверждение. Confirm повторно проверяет
весь набор до первой записи пилота/результата. Остальные ошибки ORM/сопоставления
команды/шасси по-прежнему обрабатываются построчно, это не обещание транзакционной
атомарности всего импорта.

Отсутствующая колонка статуса сохраняет ранее установленный вручную статус.
Явная пустая колонка снимает его. Статус не пересчитывает очки из protocol.
У combined CSV каждая строка относится к своей session_type. Final обновляет
финальное position, qual/pre_final его не затрагивают.

## Рейтинг

`analytics/core/results.py::ranked_rows` допускает положительные финальные места
с пустым final_status или DNF. DNS, DQ финала, нулевые/отрицательные места
не участвуют. DQ квалификации/предфинала не отменяет действительный финал.
DataLoader читает только опубликованные EventPage; сохраняет status-поля для
проверки допуска. Отдельные функции обучения также применяют ranked_rows.

В BT виртуальное поражение возможно только при настоящем отсутствии строки
пилота в группе после его первого допущенного старта. Присутствующая строка
DNS/DQ/без места освобождает от такого поражения. Она не устанавливает дату
первого допущенного старта и не увеличивает число допущенных стартов.

`min_races_per_class=3` — минимум трёх **разных group_id** с допущенными
результатами класса. `min_comparisons` проверяется отдельно. Порог относится
к BT; отдельные настройки/пороги context/PR не переименованы.
Успешный BT-пересчёт заменяет весь rating_by_class, чтобы после изменения
допуска/порога не сохранялись прежние BT-баллы исключённого пилота/класса.
Численные формулы BT, временные веса, сглаживание и переходы класса не менялись.

## Рекорды и дата

`website/services/race_results.py` — общий источник публикационного отбора,
допуска сессий, лучшего круга и даты. DQ/DNS-сессии не дают кругов/секторов;
действительные круги до DNF допустимы. Минимум времени — строго положительный.
Правила используются RaceResult.best_lap_all_ms/best_lap_session, идеальным
кругом, статистикой трассы и вычислением records_cache для профиля/SetupKart.
Не следует требовать положительного финального места для рекорда квалификации.

Каноническая дата — последнее окончание occurrence в часовом поясе сайта.
Для legacy-страниц без occurrence используется last_published_at, затем
first_published_at. Полностью недатированные записи не дают рейтинговых данных
и рекордов. Ограничения правдоподобия секторов страницы трассы сохраняются.

SetupKart не отдаёт materialized record, если событие уже скрыто либо его
допустимый лучший круг больше не совпадает со снимком. Это не заменяет
контролируемую перестройку всех materialized данных после правок.

## Применение и проверка

Миграция `website.0110_analytics_min_class_races` меняет default/описание
порога и задаёт существующим AnalyticsSettings значение 3. Она подготовлена,
но в рамках исправлений **не применялась к существующим БД**.
Перед любыми дальнейшими изменениями БД по указанию владельца необходим бэкап.
Автоматического пересчёта или миграции при старте приложения нет.

Существующие rating_by_class, records_cache и page-cache остаются снимками
предыдущего состояния до отдельного контролируемого обновления. Исторические
CSV, где статус уже потерян, нельзя однозначно восстановить по нулю: нужен
проверенный исходный протокол. Массовое восстановление данных здесь не выполнялось.

Регрессионные тесты — `website/tests/test_result_data_rules.py`.
Изолированный runner — `diagnostics/data_fixes_20261030/run.py`: отдельный
PostgreSQL Unix socket без TCP, закрытые рабочие DSN и .env, locmem-почта/кэш,
`--nomigrations --reuse-db`. Проверка миграции здесь проверяет только её
data-функцию на тестовой БД, не всю историческую цепочку миграций.
Исторические отчёты GripLine_code_research.md и GripLine_data_checks.md
описывают состояние до исправлений и намеренно не переписаны.
