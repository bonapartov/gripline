# Пульт Gripline и утренняя сводка

> Перенесено из `CLAUDE.md` 27.10.2026 без изменений текста. Общие правила проекта — в `CLAUDE.md`.

## Главная страница админки — «Пульт Gripline» и утренняя сводка (реализовано 2026-10-07)

На `/admin/` (Wagtail dashboard) над стандартными панелями выводится панель `website/dashboard/panels.py::DashboardPanel` (хук `construct_homepage_panels` в `wagtail_hooks.py`), шаблон `templates/dashboard/panel.html`. Блоки: **Требует внимания** (очереди: заявки пилотов `DriverClaim`, команд `TeamClaim`, на участие `Application.submitted`, обращения по ПД с просрочкой, обращения бота и «без ответа > 48 ч», неопубликованные страницы); **Что нового** (счётчики с выбором окна — «с прошлого визита» / 24 ч / 7 дней, `?dash=`); **Состояние системы** (бот — heartbeat, бэкап БД — возраст файла в `settings.BACKUP_DIR` (по умолчанию `/backups`), диск, почта (кил-свитч), FastAPI и прокси Telegram — короткие TCP-пробы только вне `DEBUG`, cron-задачи); **Рейтинг и результаты** (последний пересчёт, «пора пересчитать», прошедшие заезды без результатов за 60 дней); **компактная статистика обращений** (только с правом `view_feedback`, ссылка на полную) и **Сайт в цифрах**.

| Файл | Роль |
|------|------|
| `website/dashboard/data.py` | Очереди, «что нового», окно визита (`touch_visit`), блок рейтинга, сводка. Только счётчики и ссылки — без ПД |
| `website/dashboard/health.py` | Проверки `(название, level ok/warn/fail/unknown)`; пробы сети выключены в DEBUG |
| `website/dashboard/jobs.py` | Реестр cron-задач `JOBS` и контекст `record_job(name)` — пишет `ScheduledJobRun`; новая cron-задача = строка в `JOBS` + `with record_job(...)` в команде |
| `website/dashboard/digest.py`, `management/commands/daily_digest.py` | Утренняя сводка в админ-чат Telegram |

**Решения, которые не очевидны из кода:**
- **Заявки в админке — всё в Wagtail** (07.10.2026): `TeamClaim`/`TeamManager`/`TeamJoinRequest` — группа «Заявки команд», `DriverClaim` — «Заявки пилотов», заявки на участие (`Application`) — «Организаторы → Заявки на участие» (`applications/wagtail_hooks.py`: список со статус-бейджем, фильтры, поиск, страница просмотра со ВСЕМИ связанными данными — заявитель, пилот, карт, механик, документы, опции, оплата; редактируются только статус, комментарий организатора, стартовый номер и класс; создания нет — заявку создаёт пользователь в кабинете). Полное редактирование с inline'ами осталось в `/django-admin/`. **Файлы заявок на странице просмотра — только имя, без ссылки**: `serve_document`/`serve_receipt` отдают их лишь заявителю и организатору этапа (результат security-аудита), админу платформы доступ не расширяли — это отдельное решение. Ссылки дашборда ведут в Wagtail-админку (раньше по ошибке в `/django-admin/`).
- **«С прошлого визита»** — `AdminDashboardVisit`: окно сдвигается только если пауза между заходами > 30 минут, иначе обновление страницы обнуляло бы счётчики. Первый заход — окно 7 дней.
- **«Пора пересчитать рейтинг»** — `UpdateLog.race_results_count` заполняется в `save()` модели (логи создаёт и `update_ratings`, и админ-кнопка), дашборд сравнивает с текущим числом `RaceResult`. У старых логов NULL → «нет данных», не ложная тревога.
- **Ни разу не запускавшаяся cron-задача — нейтрально (unknown), не сбой**: сразу после деплоя это нормально. Сбой — когда молчит дольше `max_age` из `JOBS` или последний запуск упал.
- **Бэкап БД** делает shell-cron вне Django (раз в неделю, `pg_dump`) — проверяется по `mtime` файла; локально папки нет → unknown.
- **Утренняя сводка**: время и включение — «Обратная связь → Настройки бота → Утренняя сводка» (`digest_time`, по Москве; кнопка «Отправить сводку сейчас» там же). Cron раз в 10 минут вызывает `daily_digest`, команда сама решает «пора ли» (`digest_due`: время наступило и сегодня ещё не отправлена, `digest_last_sent_on`) — поэтому смена времени не требует правки crontab, а пропущенное окно (сервер лежал) наверстывается в тот же день. Неотправленная сводка = сбой запуска (виден на дашборде). Неопубликованные страницы в сводку не идут (не срочно). Без ПД: только счётчики и статусы.
- Cron на проде (добавить один раз): `*/10 * * * * cd /www/wwwroot/gripline.ru && venv/bin/python manage.py daily_digest >> /var/log/gripline-digest.log 2>&1`.
