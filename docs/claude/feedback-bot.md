## Бот обратной связи (Telegram, реализовано 2026-10-06)

Пилоты/команды/клубы пишут боту `@gripline_support_bot` об ошибках в данных, предлагают трассы/этапы/идеи, пишут по сотрудничеству; модераторы разбирают обращения в закрытой супергруппе. Полное ТЗ v1.0 — вне репозитория, у пользователя. Бот живёт внутри Django-проекта: `manage.py run_feedback_bot` (aiogram 3, long polling), общая БД и модели, отдельный systemd-процесс. FastAPI не используется.

**Всё настраивается в админке** — раздел **«Обратная связь»** в боковом меню Wagtail: «Обращения» (список/просмотр/смена статуса), «Настройки бота», «Категории и шаги», «Тексты бота», «Модераторы», «Пользователи бота». В `env` только `FEEDBACK_FERNET_KEY` (ключ Fernet; потеря = повторный ввод токена). Токен бота хранится в БД шифртекстом, в админке маскируется (`123456:AA••••`), пустое поле при сохранении = «не менять».

**Первичная настройка на проде (одноразово):**
```bash
# 1. Ключ шифрования в /www/wwwroot/gripline.ru/.env
python -c "from cryptography.fernet import Fernet; print('FEEDBACK_FERNET_KEY=' + Fernet.generate_key().decode())" >> .env
# 2. Зависимости, миграции, systemd-юнит
pip install -r requirements.txt && python manage.py migrate
cp deploy/systemd/gripline-feedback-bot.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now gripline-feedback-bot
# 3. Анонимизация по сроку хранения — cron раз в сутки
#    15 4 * * * cd /www/wwwroot/gripline.ru && venv/bin/python manage.py feedback_cleanup
```
Дальше в админке: «Настройки бота» → токен, `ID админ-чата`, включить → «Сохранить» → «Проверить соединение» → «Тест админ-чата» → «Создать темы по категориям» (в супергруппе включены «Темы», у бота право «Управление темами»). Модераторов добавить в «Модераторы» — числовой Telegram ID человек узнаёт командой `/id` в личке с ботом. Бот пишет heartbeat раз в 30 с (индикатор в «Настройках бота»).

**Прокси:** как у остальных интеграций — галочка `use_vpn` в настройках бота, сам адрес — централизованно в «Интеграции → VPN» (`VpnSettings`). Прод не видит `api.telegram.org` напрямую. aiohttp-socks не знает схему `socks5h://` — адаптер сам заменяет её на `socks5://` (для python-socks разрешение имён на стороне прокси и так поведение по умолчанию).

**Применение настроек.** Тексты, лимиты, категории и шаги бот читает из БД при каждой операции — действуют сразу, без перезапуска. Раз в `settings_refresh_sec` supervisor сверяет только то, что требует пересоздания клиента Telegram: токен, прокси, `is_enabled`, `restart_requested_at` (кнопка «Перезапустить бота»). При изменении процесс корректно завершается с кодом 0, systemd поднимает его заново. При `is_enabled=False` или пустом токене процесс не падает, а ждёт.

**Файлы (`website/feedback/`):**

| Файл | Роль |
|------|------|
| `service.py` | Ядро: сценарий, лимиты, статусы, анонимизация. **Не импортирует aiogram**, функции синхронные (адаптер зовёт через `sync_to_async`) |
| `channels/base.py` | Интерфейс `ChannelAdapter` — второй канал (MAX, VK) = ещё один адаптер |
| `channels/telegram.py` | Адаптер: карточка в админ-чат (очередь с повтором при 429), темы, вложения |
| `telegram_bot.py` | Обработчики aiogram + supervisor/heartbeat |
| `autoreply.py` | Точка расширения `AutoReplyProvider` (сейчас заглушка `NullAutoReply`) |
| `sources.py` | Реестр deep links: `s`=`EventPage`, `p`=`Driver`, `t`=`Track`, `c`=`ChampionshipPage`, `h`=`StagePage` (общая страница этапа), `r`=рейтинг класса (`/top/drivers/?class=<id>`) |
| `admin.py`, `admin_views.py`, `tg_sync.py` | Админка, кнопки проверки/теста/перезапуска/создания тем, выдача вложений |
| `crypto.py`, `storage.py`, `texts.py` | Fernet, закрытое хранилище, тексты по умолчанию (единственный источник ключей `FeedbackText`) |
| `templatetags/feedback_tags.py` | `{% feedback_link %}` — кнопка «Сообщить об ошибке» |

**Решения, которые не очевидны из кода:**
- **«Этап» в deep links — это `EventPage`**, не `StagePage`: на странице класса лежат таблица результатов и хронометраж, `StagePage` — только хаб с датами/трассой. Новый вид объекта = одна строка в `sources.RESOLVERS`. Формат ссылки `t.me/<бот>?start=<код>_<s|p|t>_<id>` (не slug: параметр `start` ≤ 64 символов и без кириллицы); `?start=err` без объекта — для страниц вроде рейтинга.
- **Состояние сценария — `FeedbackDraft` в БД**, не `StatesGroup` aiogram: сценарии редактируются в админке, а черновик должен переживать перезапуски бота (в т.ч. от смены настроек). Незавершённые черновики чистит `feedback_cleanup` (24 ч). `FeedbackStep` — `Orderable` + `ParentalKey` (порядок перетаскиванием, шаги редактируются инлайном в категории).
- **Вложения не в `MEDIA_ROOT`** (его публично раздаёт nginx): `PRIVATE_MEDIA_ROOT = BASE_DIR/'private_media'` (в `.gitignore`), у `FileField` нет публичного URL (`PrivateStorage.url()` бросает `ValueError` — `FileSystemStorage(base_url=None)` подставил бы `MEDIA_URL`), отдача только через `/admin/feedback-bot/attachment/<id>/` с правом `view_feedback`. Тип проверяется по содержимому (`filetype`), не по расширению.
- **Права:** доступ к «Обращениям» (`view_feedback`) выдаётся отдельно от «Настроек бота» (`change_feedbackbotsettings`) — модератору можно дать только обращения.
- **Анонимизация** (`/forget`, `feedback_cleanup` по `retention_months`): ссылка на пользователя обнуляется, ответы/сообщения/файлы удаляются, статус+категория+даты остаются; карточка в админ-чате редактируется, не удаляется. Пользователь удаляется целиком, **кроме забаненного** — у него остаётся только факт бана без username/имени, иначе бан слетел бы.
- **Диалог**: пока обращение `new`/`in_work`, текст пользователя уходит в тему этого обращения (reply на карточку). Модератор отвечает reply на карточку или любое сообщение диалога (`Feedback.admin_chat_message_id` + `FeedbackMessage.admin_chat_message_id`). Файлы вне сценария не принимаются (только текст). Ответ модератора доходит двумя путями. (1) **Reply на карточку** (или на любое сообщение бота с «№N», в т.ч. подсказку кнопки) — однозначен, уходит сразу. (2) **Кнопка «Ответить»**: бот запоминает в памяти (`_pending_replies`, ключ — чат+тема, TTL 5 мин, одноразово) обращение, следующее обычное сообщение в теме НЕ уходит сразу, а показывается с кнопками «✅ Отправить / Отмена» (`fbc:<token>:yes|no`, `_confirmations`). Причина: тема общая на категорию, а анонимный админ неотличим от других — без подтверждения текст мог уйти не тому пользователю. `ForceReply` в подсказке оставлен, но у администратора, пишущего от имени группы, Telegram панель ответа не открывает — на него рассчитывать нельзя. Подтвердить может только активный модератор (в `FeedbackMessage.moderator` пишется нажавший). Обычное сообщение в теме без нажатой кнопки бот игнорирует. Анонимный админ группы (сообщение «от имени группы») допускается без привязки к человеку (`_moderator_of`, проверяется `sender_chat == админ-чат`).
- **Виджет «Обратная связь»** (плавающая кнопка справа внизу + окно, `{% feedback_widget %}` в `templates/coderedcms/pages/base.html`, `includes/feedback_widget.html`, `css/feedback-widget.css`, `js/feedback-widget.js`). Пункты окна — активные категории из админки с кодом deep link (порядок, названия, «Подсказка в виджете» правятся в «Категории и шаги»). Контекст страницы (`EventPage`→`s`, `StagePage`→`h`, `ChampionshipPage`→`c`, `Driver`→`p`, `Track`→`t`; вьюха без Wagtail-страницы может задать его явно: `feedback_source=('rating', <id класса>)` в контексте — так делает `top_drivers_view`) подставляется только в категории, у которых есть шаг с `skip_if_source_set`. Не выводится, если бот выключен/нет юзернейма/нет категорий; `/balance/` не затронут (свой `app_base.html`); пока показана плашка cookie (`body:has(.gl-cookie)`) — скрыт. Нейтральное «Обратная связь» вместо «Сообщить об ошибке» — сознательно (решение 06.10: «ошибка» на каждой странице выглядит как признание, что на сайте их много). На рейтинге класс переключается AJAX'ом (`pushState ?class=ID`), поэтому ссылки с `data-fb-template` пересобираются JS виджета при открытии окна. Порядок пунктов — поле «Порядок» категории (общий с меню бота). Конфиг кэшируется на 60 с, страницы — ещё и `wagtailcache`: после правок/включения бота выполнить `clear_wagtail_cache` на проде. Цели Метрики: `feedback_widget_open`, `feedback_widget_click` (параметр `category`) — работают только после согласия на аналитику.
- **`/feedback/`** (`feedback/public_views.py`) — редирект на `t.me/<юзернейм из настроек>` (`?c=<код>` открывает категорию): для мест, где юзернейм не подставить из настроек (HTML футера в БД-сниппете, письма, соцсети). При выключенном боте ведёт на `/`. Строка «Обратная связь» в подвале: во встроенном `footer_default.html` есть, а **прод-футер — сниппет Footers в БД**, правится в админке отдельно.
- **Урок:** `driver_page.html` переопределял `{% block custom_scripts %}` без `{{ block.super }}`, поэтому на страницах пилотов не было ни плашки cookie, ни Метрики (плашку добавили только в `base.html`). Любой шаблон, переопределяющий `custom_scripts`, обязан вызывать `{{ block.super }}`.
- **Статистика обращений** — «Обратная связь → Статистика» (`/admin/feedback-bot/stats/`, `website/feedback/stats.py` + `templates/feedback/admin/stats.html`, право `view_feedback`). Считается на лету, без таблиц и без ПД: период (7/30/90/365/всё), карточки (всего/авторов, открыто сейчас — не зависит от периода, закрыто, медиана до первого ответа и до закрытия), предупреждение «без ответа > 48 ч», график по дням, категории, типы источников, топ страниц с жалобами. Анонимизированные обращения учитываются в счётчиках, но не в скорости ответа (их сообщения удалены). Метки «взяли в работу» нет — время реакции считается по первому ответу модератора. Акцентный цвет — зелёный `--w-color-positive-100` (фиолетовый primary Wagtail заменён по просьбе пользователя).
- **Обращения к БД из бота — только через `website/feedback/db.py::run_sync`** (внутри `close_old_connections()`): процесс долгоживущий, без этого после перезапуска PostgreSQL (09.10.2026 — автообновления Ubuntu в 06:42) бот держал мёртвое соединение, heartbeat не писался, сводка показала «Бот молчит». Не вызывать `sync_to_async` с ORM напрямую. У FastAPI по той же причине `pool_pre_ping=True`.
- **Команда `/id`** в личке с ботом — не из ТЗ, добавлена, чтобы модератор мог узнать числовой ID для списка «Модераторы». Дополнительные ключи `FeedbackText` (кнопки, подсказки) тоже сверх списка из ТЗ.
- **Баг, пойманный тестами обработчиков, а не сервисными:** `answer_text` менял `draft.answers`, но `_next` сохранял только `step_index` — ответы терялись между сообщениями. Сервисные тесты не ловили (один объект в памяти), поймал прогон через `dp.feed_update` на фейковой сессии. Тест `test_answers_survive_reloading_draft_from_db` фиксирует.

**Тесты:** `website/tests/test_feedback_{service,admin,bot,link}.py` (обработчики — на `FakeSession(BaseSession)` без сети; `transactional_db` обязателен: `sync_to_async` работает в другом потоке и не видит незакоммиченные данные обычной `db`; логин в админ-тестах — `force_login`, `client.login` ломает django-axes).

**Не сделано (по ТЗ — «Потом»):** автоответы, статистика обращений, второй канал, роли модераторов, показ связанного объекта в админке со ссылкой (в карточке в Telegram он есть).
