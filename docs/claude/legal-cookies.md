# Правовые страницы, форма ПД, cookie-согласие

> Перенесено из `CLAUDE.md` 27.10.2026 без изменений текста. Общие правила проекта — в `CLAUDE.md`.

## Правовые страницы и форма обращения по ПД (реализовано 2026-10-05)

- **Страницы** `/legal/` (оглавление), `/legal/privacy/` (Политика обработки ПД), `/legal/terms/` (Пользовательское соглашение) — `WebPage` с html-блоком. Тексты лежат в `website/legal_pages/*.html` с плейсхолдерами `{{OPERATOR}}`/`{{TG}}`/`{{DATE}}`; ФИО оператора и Telegram в репозитории не хранятся, подставляются при запуске: `python manage.py create_legal_pages --operator "…" --tg "@…" --publish` (идемпотентно; без `--publish` — черновики). Команда же ставит редирект `/privacy-policy/` → `/legal/privacy/`. Текст правится в `website/legal_pages/`, затем команду нужно запустить на проде заново (в БД лежит копия).
- **Уведомление в Telegram** о новом обращении (`website/feedback/notify.py`, вызывается из `legal_views._submit`): в админ-чат бота обратной связи уходит тип, срок и ссылка на админку — **без контакта и текста заявителя** (ПД в групповой чат не кладём). Нужны только токен и `admin_chat_id` в «Настройках бота», запущенный процесс бота не обязателен (прямой вызов Bot API через `tg_sync`, тот же прокси). Настройки читаются в основном потоке, в фоновом потоке — только сетевой вызов с таймаутом 8 с: ни задержка, ни сбой Telegram не ломают приём обращения.
- **Форма** `/legal/data-request/` (`website/legal_views.py`, `templates`: `website/templates/legal/data_request.html`) — по образцу kartracers.ru, в токенах `--gl-*`. Обращения хранятся в `DataRequest` (админка → «Обращения по ПД», срок ответа 10 рабочих дней), а не только письмом: исходящий SMTP на проде может быть заблокирован, сбой письма обращение не теряет. Honeypot + лимит 5/час с IP; `@nocache_page` обязателен (CSRF + сессионное «спасибо»). После рассмотрения админ очищает контакт/текст (политика п. 6.1).
- **Подвал:** столбец «Документы» (политика, соглашение, обращение по ПД) после «Личного кабинета»; в нижней строке «Оператор персональных данных: см. политику конфиденциальности».
- **Cookie-согласие (2026-10-05):** плашка «Принять аналитику / Только необходимые» — `website/static/website/js/cookie-consent.js` + `css/cookie-consent.css`, подключается одним инклюдом `website/templates/includes/cookie_consent.html` (base.html сайта и `balance/app_base.html`). Выбор — cookie `gl_cookie_consent` (`all`/`necessary`, ~180 дней). **Яндекс Метрика (id 108405016) и Вебвизор грузятся только из этого скрипта и только после `all`** — не добавлять тег Метрики/`<noscript>`-пиксель в шаблоны напрямую. **Google Analytics (с 18.10.2026)** — так же: идентификатор в админке «Настройки → Трекинг» (поле Google Analytics, `coderedcms.AnalyticsSettings.ga_g_tracking_id`) → атрибут `data-ga-id` → грузится `cookie-consent.js` после `all`, при отзыве стираются `_ga*`. Безусловная вставка CodeRed в `<head>` (`{% block tracking %}`: GA, GTM, «скрипты в head») в `base.html` выключена — GTM и «скрипты в head» из админки на сайт не попадают. Отзыв («Настройки cookie» в подвале и на `/legal/cookies/`, любой элемент с `data-cookie-settings`) стирает cookie `_ym*/_ya*` и перезагружает страницу. `/balance/` шлёт цели `ym(...,'reachGoal')` только если `window.__balanceYmCounter` выставлен (его ставит loader после согласия). Страница политики — `website/legal_pages/cookies.html` (`/legal/cookies/`); при появлении новых cookie/localStorage-ключей дополнять таблицу 2.1 там.
- **Согласие на медсправку (17.10.2026, `applications/health_consent.py`).** Медсправка (тип `medical`) загружается только с отметкой согласия на сведения о здоровье — в заявке, на странице заявки команды и в ЛК; пилот даёт согласие, команда/организатор подтверждают, что оно получено. Кто и когда отметил — `health_consent_at/_by` у `ApplicationDocument` и `PilotDocument`, переносится при копировании ЛК ↔ заявка; организатор видит дату отметки. Позиция владельца: сайту эти сведения не нужны, справка хранится только для передачи организатору (так и в политике, п. 4.4).
- **Редакция политики 17.10.2026:** вход по e-mail/Telegram/Яндекс/VK, регистрация на этапы, документы участника и медсправка (сведения о здоровье), заявки команд (членство в команде = согласие на доступ менеджеров к документам), доступ к файлам заявок администратора, бот обратной связи; раздел про `/balance/` заменён ссылкой на политику приложения. Пункты 4.7–4.8 и «Пол и дата рождения» описывают функции, которых на сайте нет, — оставлены как были (текст владельца).
