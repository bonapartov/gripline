# Приложение GripLine SetupKart — серверная часть

> Перенесено из `CLAUDE.md` 27.10.2026 без изменений текста. Общие правила проекта — в `CLAUDE.md`.

## Мобильное приложение GripLine SetupKart — серверная часть (реализовано 2026-10-08)

Само приложение (Flutter, Android) — **отдельный репозиторий** `/home/v/gripline-setupkart` (ТЗ `docs/TZ.md`, поля `docs/appendix_A.md`). Здесь — только то, что нужно приложению от сайта (ТЗ приложения §13).

**Принцип:** справочники сайта (`Engine`, `Chassis`, `TyreBrand`, `Track`, `RaceClass`) не дублируются и не переносятся — приложение ссылается на них. Галочка **`show_in_app`** («Показывать в приложении», по умолчанию выключена) у двигателей, шасси, производителей шин и трасс; в приложение уходит только отмеченное **и** опубликованное на сайте (`live`).

- **Вкладка «Приложение» в карточке двигателя** («Техника → Двигатели»): семейство (для импорта `.kart`), классы (`app_race_classes`), **поля карбюратора** (`AppEngineField`: тип из фиксированного набора ключей, значения — диапазон мин/макс/шаг или список, по умолчанию, «Другое…») и **свечи** (`AppEngineSparkPlug`). Все технические данные двигателя — в одном месте.
- **Меню «Приложение»** (`SetupKartGroup`, право `website.change_appparameter`): «Обзор» (что уходит в приложение), «Параметры» (`AppParameter`: ступица, пиньон, звёздочка, проставки; проставки — «−/+» в приложении), «Предложения пользователей», «Публикация».
- **Публикация** (`website/setupkart/catalog.py`): приложение получает только `AppCatalogVersion` — снимок, собранный кнопкой «Опубликовать». Перед публикацией проверка (`spec.py::spec_errors`: шаг > 0, мин < макс, по умолчанию в диапазоне/списке, у отмеченного двигателя есть поля). Ошибочную версию опубликовать нельзя.
- **API** (`website/setupkart/api.py`, `/api/setupkart/…`, все `@nocache_page` — иначе wagtailcache отдал бы старую версию): `GET catalog/?since=N`, `GET tracks/?since=<hash>` (трассы — сразу, без публикации; только с координатами), `POST suggestions/` (анонимные предложения из «Другое…», группируются в `AppSuggestion`; в админке «Добавить в справочник»/«Скрыть»; поле-диапазон автоматически не расширяется), `POST feedback/`. Ограничение частоты — по `mysite.security.get_client_ip` (последний хоп XFF, не подделывается) и `client_id`.
- **Обратная связь из приложения** (`website/setupkart/feedback.py`): обращение в системе бота — канал `setupkart` (`FEEDBACK_CHANNEL_SETUPKART`), категория `setupkart` «📱 GripLine SetupKart» с **`is_active=False`** (нет в меню бота и виджете сайта), но тема в админ-чате ей создаётся (`tg_sync.create_category_topics`). Карточка уходит в тему прямо из Django через Bot API, **без кнопки «Ответить»** и без e-mail; e-mail для ответа — только в письме администратору (`emails/admin_app_feedback`) и во внутренней заметке. `TelegramAdapter.send_message` для пользователя не из Telegram бросает `DeliveryError` — бот пишет модератору «не доставлено», ответ только по e-mail.
- **«Рекомендовать приложение»** (10.10.2026): текст и ссылка — «Приложение» → «Связь и „О приложении“» (`AppSyncSettings.share_text`/`share_url`, миграция `0068`); `{link}` в тексте — место ссылки, без него ссылка в конце. Уходит в `config/` как `share.text` (уже со ссылкой); приложение отправляет его через системное «Поделиться». Без перевыпуска приложения, при следующей связи.
- **Фото при запуске** (10.10.2026): `AppSyncSettings.splash_image` (миграция `0069`, там же, где «О приложении») → `config/` → `splash` {url,width,height} (WebP до 1440×3200), без «Публикации». Приложение скачивает его при связи и показывает на весь экран не меньше `splash_seconds` (поле рядом, миграция `0071`, по умолчанию 2 с, 0–10; нажатие закрывает сразу) — со следующего запуска; системную заставку Android (до старта Flutter) из админки не поменять.
- **Pro-версия** (10.10.2026, этап 1 — без оплаты): «Приложение» → «Pro-версия» (`AppProSettings` singleton + инлайн `AppProFeature`, миграция `0070`). Список функций — в коде (`APP_PRO_FEATURES`: лимиты `saved_sessions`/`karts`/`engines` и переключатели Бесплатно/Pro), в админке только выбор и лимиты; записи создаёт `AppProSettings.get()`. По умолчанию `enabled=False` — в приложении всё бесплатно. `config/` → `pro` {enabled, trial_days, price, purchase_url, description, features}. Модель — бесплатно + разовая покупка Pro, оплата — RuStore (этап 2). Правило: сохранённое пользователем не блокируется, лимит запрещает только создавать сверх него.
- **Развесовка в приложении** (11.10.2026): раздел «Развесовка» в сессии приложения. Пороги и тексты диагностики берутся из «Развесовки» (`BalanceThreshold`/`BalanceDiagnosticRule`) → справочник `balance` {thresholds, rules{text, article_url}}; минимальный вес — `RaceClass.min_weight_kg` (миграция `0072`, один справочник классов для сайта, `/balance/` и приложения; `Setup.race_class`, тип шасси класса пуст — класс доступен любому карту). Изменения доходят после «Публикации». Формулы — три копии (Python `balance_calc.py`, JS `balance-calculator.js`, Dart в приложении), общие контрольные примеры `website/tests/fixtures/balance_vectors.json` (копия в приложении `test/fixtures/`; `ballast_cases` — углы после грузов); JS проверяется тем же файлом через Node (`website/tests/test_balance_vectors_js.py` + `tests/js/balance_vectors_runner.cjs`, формулы отдаются через `module.exports` только вне браузера; без Node тест пропускается). **Грузы в приложении** (11.10.2026) — только на сиденье, схема карта — тот же векторный контур, что на `/balance/` (атрибут `d` из `balance/home.html` лежит в приложении ассетом `assets/kart/kart_top_web.path`, оси/края колеи — `SCHEMA` из `balance-calculator.js`); при замене схемы на сайте обновить и ассет, и контур сиденья в приложении. Пороги на проде заведены 11.10 по ТЗ §3.2. Диагностика в приложении — Pro (`balance_diagnosis`).
- **Картинки карбюратора** (09.10.2026): `Engine.app_carburetor_image` (вкладка «Приложение», миграция `0065`) — в справочнике `engines[].carburetor_image`, в приложении по центру раздела «Карбюратор» над полями; `AppHelpImage` с ключом `needle_position` (миграция `0064`) — фото иглы слева от выбора 1–5. Доходят до телефона после «Публикации».
- **Эталон развесовки по классу** (11.10.2026): у `BalanceThreshold` необязательный `race_class` (миграция `0076`): без класса — общий порог (им считает `/balance/`, `load_thresholds()` берёт только общие), с классом — эталон класса в приложении, заменяет общий порог своей метрики (справочник: `balance.class_thresholds` {id класса: {метрика: зоны}}, после «Публикации»). Зоны, диагностика и цель центра тяжести в приложении — по эталону класса сессии.
- **Поля шасси по статье «Настройка шасси карта»** (11.10.2026): схождение (`toe_mm`), распорки сиденья (`seat_strut_left/right`), передний/задний стабилизатор (`torsion_front/rear`), сиденье (`seat_shift_mm`, `seat_raise_mm`), зацеп трассы (`grip_level`), влажность и давление на трассе (`humidity_pct`, `air_pressure_hpa`) → плотность воздуха RAD. Поля — во встроенном профиле приложения (`assets/profiles/common.json`, признак `"pro": "<функция>"`); диапазоны/списки — «Приложение» → «Параметры» (`toe_mm`, `seat_strut`, `seat_shift_mm`, `seat_raise_mm` — числа «−/+», `STEPPER_KEYS`; `torsion_bar`, `grip_level` — списки), бесплатно/Pro — «Pro-версия» (`toe`, `seat_struts`, `torsion_bars`, `seat_position`, `grip_level` — бесплатно, `air_density` — Pro). Пары лево/право в приложении — в одну строку («Камбер левый/правый» — бывший «Развал»). RAD считается в приложении (формула — физика, не настройка); давление MET (уровень моря) пересчитывается на высоту точки из ответа MET. Справочник v20.
- **Рекомендации производителя по классу** (11.10.2026): двигатель → «Приложение» → «Рекомендация по классу» (`AppEngineClassPreset`, миграция `0080`): класс, поле, значение (как в списке поля) и/или диапазон. Справочник: `engines[].class_presets` {id класса: {поле: {value, from, to}}}. В приложении значение подставляется при выборе двигателя/класса в поля, которые пользователь не менял; под полем — «Рекомендация производителя: 115 (112–118)» и «Подставить». Только диапазон (температура воды) — подсказка без подстановки. Заведено для Rotax FR 125 (RM Micro/Mini/Junior/Senior, таблица Rotax: жиклёр, высота/провал поплавка, воздушный винт, температура воды), справочник v19. Новые ключи полей: `float_height_mm`, `float_drop_mm`, `water_temp_c`.
- **Жиклёр по погоде** (12.10.2026): двигатель → «Приложение» → «Жиклёр по погоде»: `Engine.app_jet_base_rad` (RAD, при котором верны базы), `app_jet_step` (округление, 1 — до целого) и инлайн «База жиклёра по классу» (`AppEngineJetBase`: класс, жиклёр, жиклёр старой версии; миграции `0083`, `0084`) → справочник `engines[].jet_by_rad` {base_rad, step, bases{id класса: {base, legacy?}}}. Формула и базы — как в Rotax MAX Jetting 2.2.4 (разобрано 12.10.2026): база × (1 + √(RAD/RAD базы)) / 2, базы при RAD 100 (ρ 1.225): Micro 111/110, Mini 117/115, Junior 129, Senior 128, DD2 132/136 (текущая/старая версия); давление в Rotax — приведённое к уровню моря и пересчитывается на высоту, как у нас. Округление до целого, **без обрезки диапазоном класса** (в мороз Rotax советует больше табличного). В приложении (Pro «Плотность воздуха») строка под «Главным жиклёром» + «Подставить»; галочка «Старая версия двигателя» в карточке двигателя (видна, если у модели есть базы старой версии). Статья Матчасти «Плотность воздуха и подбор жиклёра» (page 487). IAME/Tillotson/ОК — без подсказки.
- **Советы по поведению карта** (12.10.2026): «Приложение» → «Советы по шасси» (`AppChassisAdvice` + инлайн `AppChassisRule`, миграции `0086`, `0087` — начальное наполнение 50 советов / 169 правил, тексты свои); правила проверены механиком 13.10.2026). Совет: что сделать, почему, картинка, поле приложения (`APP_ADVICE_TARGETS`: код → поля профиля, пары лево/право вместе) и кнопка «Применить» (на шаг больше/меньше по числу или списку, «Установить» значение). Правило: симптом × фаза поворота → сила (сильно/средне/слабо), эффект, условие по доле балласта и погоде. Логика «симптом → регулировка» — по разбору Kart Chassis Setup Pro 1.4.1 (12.10.2026, только правила и числа; `docs/chassis_analysis_rules.md` в репозитории приложения). Справочник `chassis_advice` (после «Публикации»), совет без правил не уходит. В приложении — раздел «Поведение карта» (Pro `chassis_advice`).
