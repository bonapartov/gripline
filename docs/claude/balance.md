### Архитектура

- **Роутинг** — простой Django `path('balance/', include('website.balance_urls'))` в `mysite/urls.py`, НЕ Wagtail Page и НЕ отдельный Wagtail Site (`django-hosts` не установлен и не нужен — единственный домен). Модели — в `website/models.py` (правило проекта «единое приложение»), views — отдельный модуль `website/balance_views.py` (по образцу `mediakit_views.py`, не раздувать `views.py`).
- **App-shell** (`website/templates/balance/app_base.html`) — без сайтового header/footer, `100dvh`, `viewport-fit=cover`, `env(safe-area-inset-*)`, нижняя таб-навигация. PWA: `manifest.json` + минимальный service worker (`website/static/website/js/balance-sw.js`, только install/activate/no-op fetch — без него Android не предложит установку вообще, реальное офлайн-кэширование — Блок 7) + баннер «Добавить на экран» после 3 визитов (localStorage-счётчик), с отдельной веткой для iOS (нет `beforeinstallprompt`, показывается инструкция). **На ПК (с 12.10.2026)** — та же телефонная колонка по центру, не растягивается: шапка и вкладки собраны в 480px (`@media (min-width: 600px)` в `balance-app.css`). Заглушка «поверните телефон» — только `(orientation: landscape) and (pointer: coarse) and (max-height: 600px)`: без этих условий она закрывала калькулятор на любом мониторе (монитор тоже landscape).
- **Расчётный слой дублирован сознательно** (ТЗ §15): `website/services/balance_calc.py` — канонический Python (тесты, серверный рендер, Блок 6 диагностика), `website/static/website/js/balance-calculator.js` — та же математика в JS для расчёта в реальном времени без похода на сервер (ТЗ §3.4). Паритет проверен вручную через Node на тех же контрольных значениях, что в pytest — при правке формулы менять оба места синхронно, иначе они разойдутся незаметно.
- **Справочники — не хардкод, а админка** (пользователь явно попросил: «нужен отдельный пункт в меню админки, в котором будут вноситься данные, которые не захардкожены»). Пункт **«Развесовка»** в боковом меню Wagtail admin (`website/wagtail_hooks.py::BalanceGroup`): `ChassisTypePreset` (геометрия по умолчанию, 2 записи junior/senior), классы — общие `RaceClass` («Классы гонок»: мин. вес, тип шасси и геометрия с переопределением в блоке «Развесовка»; отдельный `KartClass` удалён 12.10.2026, миграция `0082`), `BalanceThreshold` (пороги цветовой индикации, 3 метрики), `BalanceDiagnosticRule` (диагностический текст Блока 6 + обучающий блок). Все графики/формулы читают эти таблицы через `website/services/balance_calc.py::load_thresholds()`/`load_diagnostic_rules()` — не через отдельные захардкоженные числа, чтобы админ-правка порога и диагностический текст не расходились между собой.

### Модели (`website/models.py`, миграции 0037–0040)

Справочники (Wagtail admin): `ChassisTypePreset`, `BalanceThreshold`, `BalanceDiagnosticRule` (текст 8 правил предзаполнен из ТЗ миграцией-данных `0040`, ссылки на статьи Матчасти — пустые, см. «Открытые вопросы ТЗ» ниже).

Пользовательские данные (обычный `django-admin`, не CMS — тот же паттерн, что `TeamManager`/`TeamClaim` в `teams/admin.py`): `TeamRosterEntry`, `Kart`, `Setup`, `Ballast`. `Kart` — DB `CheckConstraint` «ровно один владелец» (пилот **или** команда, не оба и не ни одного) — проверено и на уровне `clean()`, и на уровне PostgreSQL напрямую. `Setup.clean()` не даёт сохранить класс, не подходящий типу шасси карта.

### Формулы (`website/services/balance_calc.py`)

- Блок 2 (§3.1-3.5): `compute_metrics`, `validate_corners`, `classify_all`, `min_weight_status`, `evaluate_setup`. Открытый вопрос ТЗ №13 (границы правдоподобия углового веса) закрыт эвристикой из самого ТЗ — предупреждение при угле выше половины `min_weight_kg` класса; без выбранного класса проверка просто не включается (не выдумывать глобальный порог).
- Блок 4 (§5.3-5.4, визуальный редактор): `ballast_deltas`, `apply_ballasts`, `center_of_gravity`, `target_center_of_gravity`. `x_front`/`x_rear` в формуле ТЗ — не два разных измерения, а один и тот же offset от левого края, делённый то на `track_front`, то на `track_rear`. Целевая точка CG (43/57+50/50) не захардкожена — середина зелёной зоны `BalanceThreshold`, с фолбэком на буквальные числа ТЗ, если пороги ещё не заведены.
- Блок 6 (§7.1, диагностика): `diagnose()` переиспользует УЖЕ настроенную классификацию green/yellow/red вместо отдельных чисел 42/44/48/52/49/51 — порог и диагностика двигаются синхронно. Нюанс ТЗ «Cross % вне 49.5–50.5 при нормальном L/R» — L/R не красный; если L/R сам красный (асимметрия по бортам), `cross_diagonal` не срабатывает, срабатывают `cross_mechanical`+`lr_asymmetry`. `wet_weather` — с 2026-09-01 срабатывает: селектор погоды `#glCalcWeather` добавлен в UI (Блок 5 частично), `currentWeather()` в `balance-calculator.js` отдаёт значение в `diagnose()`.

**57 тестов** (`website/tests/test_balance_calc.py`) — формулы Блоков 2/4/6, включая весь чек-лист ТЗ §3.6 (сумма Δ = масса груза, груз по центру → симметрично, груз над углом → вся масса туда, отрицательный груз, CG до/после добавления, нулевая геометрия, груз за пределами колеи).

### SEO (Блок 8, `website/schema.py`, `website/sitemaps.py`, `website/balance_views.py`)

`/balance/` — не Wagtail Page, поэтому не подхватывается автоматически ни `wagtail-seo` (`SeoMixin` только на Page), ни sitemap.xml (`wagtail.contrib.sitemaps` строит дерево только из `Page.objects.live()`) — оба вопреки прямым формулировкам ТЗ («используем уже установленный wagtail-metadata», «Wagtail генерирует sitemap штатно, /balance/ попадает автоматически»). ### Найденные и исправленные попутные баги

1. **Дубли `AddField` в миграции `0013`** — см. «Тестовая инфраструктура» выше.
2. **`ArticlePage.get_absolute_url()` не существует** — Wagtail Page использует `.url`, не Django-конвенцию `get_absolute_url()` (та — у `Driver`/`Team`/`Chassis`, не у Wagtail-страниц). Поймано живым 500-м при первой проверке привязки статьи к диагностическому правилу, не мимоходом.
3. **Блокировка ландшафтной ориентации (ТЗ §3.4) не работала ни разу с самого Блока 2.** CSS-селектор требовал `.gl-balance-content.gl-balance-orientation-sensitive` (оба класса на одном элементе), а по факту `gl-balance-orientation-sensitive` — на вложенном `<div>` внутри `<main class="gl-balance-content">`. Найдено не в браузере (проект не проверяется во фронтенде самостоятельно, см. ниже), а при повторном чтении вёрстки под Блок 8.
4. **`/privacy-policy/` в футере сайта вела в 404** — см. «Персональные данные» выше.
